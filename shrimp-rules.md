# AI Agent Development Standards

## Project Overview

- **Technology Stack**: Next.js 15.3.3 + TypeScript + Tailwind CSS v4 + shadcn/ui + Zustand + TanStack Query
- **Package Manager**: pnpm (specific version: 10.8.0)
- **Architecture**: Feature-based organization with strict component separation
- **API Integration**: OpenAPI-generated TypeScript clients with environment-specific endpoints

## Critical File Modification Rules

### **ALWAYS Prioritize Editing Over Creating**

- **NEVER** create new files unless absolutely required
- **ALWAYS** modify existing files instead of creating duplicates
- **NEVER** create documentation files unless explicitly requested
- **REQUIRED**: Use `Read` tool before any file modification

### **File Creation Restrictions**

- **PROHIBITED**: Creating files in `/src/apis/main/` (auto-generated by OpenAPI)
- **PROHIBITED**: Creating duplicate components that already exist
- **REQUIRED**: Follow existing file naming patterns exactly
- **REQUIRED**: Create index.ts files when adding new component directories

## Component Architecture Standards

### **Feature-Based Organization**

- **REQUIRED**: Place feature-specific components in `src/features/{feature}/components/`
- **REQUIRED**: Place shared base components in `src/components/base/`
- **REQUIRED**: Place layout components in `src/components/layout/`
- **PROHIBITED**: Mixing feature components with base components

### **Component Export Patterns**

```typescript
// Base components (src/components/base/*/index.ts)
export { ComponentName } from './ComponentName'
export type { ComponentProps } from './component.types'

// Feature components (src/features/*/components/index.ts)
export { default as ComponentName } from './ComponentName'
```

### **Component File Structure**

```
src/components/base/component-name/
├── Component.tsx          // Main component
├── Component.types.ts     // TypeScript interfaces
├── Component.styles.ts    // Style variants (if needed)
├── index.ts              // Exports
```

### **React Component Declaration**

```typescript
// REQUIRED: Use export function (not const)
export function ComponentName({ prop }: Props) {
  return <div>{prop}</div>
}

// PROHIBITED: const ComponentName = () => {}
```

/**

## Quality Assurance Requirements

### **MANDATORY After Every Significant Change**

1. **REQUIRED**: Run `pnpm type-check` before completion
2. **REQUIRED**: Run `pnpm lint` to check for issues
3. **REQUIRED**: Run `pnpm fix:lint` to fix linting issues
4. **REQUIRED**: Run `pnpm fix:prettier` for formatting

### **Code Quality Standards**

- **REQUIRED**: Follow strict TypeScript configuration
- **REQUIRED**: Use existing utility functions from `src/lib/utils.ts`
- **REQUIRED**: Import styles using `cn()` utility for conditional classes
- **PROHIBITED**: Bypassing TypeScript strict mode

## Environment and Development

### **Environment-Specific Commands**

- **Development**: `pnpm dev` (with codegen) or `pnpm dev-without-codegen`
- **Production**: `pnpm prod` (with codegen) or `pnpm prod-without-codegen`
- **Local**: `pnpm local` (with codegen) or `pnpm local-without-codegen`

### **API Integration Rules**

- **PROHIBITED**: Modifying files in `src/apis/main/` (auto-generated)
- **REQUIRED**: Use `pnpm codegen:dev|prod|local` when API schemas change
- **REQUIRED**: Use environment-specific endpoints for API calls

## State Management Patterns

### **Zustand Store Structure**

- **REQUIRED**: Place stores in `src/stores/` with descriptive names
- **REQUIRED**: Export store hooks, not the store itself
- **EXAMPLE**: `useViewportStore.ts` pattern

### **TanStack Query Integration**

- **REQUIRED**: Place query hooks in `src/queries/`
- **REQUIRED**: Use CustomQueryClientProvider for error handling
- **REQUIRED**: Handle 401 errors through existing global error handler

## UI Component Standards

### **shadcn/ui Integration**

- **REQUIRED**: Use existing components from `src/components/ui/`
- **REQUIRED**: Follow New York style variant with CSS variables
- **REQUIRED**: Use Lucide React for icons
- **REQUIRED**: Use Sonner for toast notifications

### **Styling Standards**

- **REQUIRED**: Use Tailwind CSS v4 classes
- **REQUIRED**: Use `cn()` utility for conditional styling
- **REQUIRED**: Follow responsive design patterns from existing components
- **PROHIBITED**: Inline styles or CSS modules

## Storybook Integration

### **Story Creation Rules**

- **REQUIRED**: Create stories in `src/stories/component/` for new components
- **REQUIRED**: Follow existing naming pattern: `ComponentName.stories.tsx`
- **REQUIRED**: Include multiple variants and states in stories

## Multi-File Coordination

### **When Modifying Layout Components**

- **Header.tsx**: May require updating responsive navigation
- **Footer.tsx**: Check mobile responsive behavior
- **MobileTopBanner.tsx**: Ensure Header height adjustments

### **When Adding Feature Components**

1. Create component in `src/features/{feature}/components/`
2. Export in `src/features/{feature}/components/index.ts`
3. Export in `src/features/{feature}/index.ts`
4. Create corresponding story in `src/stories/component/`

### **When Adding Base Components**

1. Create directory in `src/components/base/`
2. Create .tsx, .types.ts, .styles.ts (if needed), index.ts
3. Export in `src/components/base/index.ts`
4. Export in `src/components/index.ts`

## AI Decision-Making Standards

### **Priority Hierarchy**

1. **Edit existing files** > Create new files
2. **Follow existing patterns** > Invent new patterns
3. **Use project utilities** > External libraries
4. **Feature-specific placement** > Generic placement

### **When Uncertain About Component Placement**

- **Feature-specific UI**: Place in `src/features/{feature}/components/`
- **Reusable across features**: Place in `src/components/base/`
- **Layout-related**: Place in `src/components/layout/`
- **Third-party integrations**: Place in `src/components/ui/`

### **Error Resolution Process**

1. Check TypeScript errors with `pnpm type-check`
2. Fix linting issues with `pnpm fix:lint`
3. Format code with `pnpm fix:prettier`
4. Verify component exports and imports
5. Test with appropriate environment command

## Prohibited Actions

### **File Operations**

- **NEVER** create files in `src/apis/main/` (auto-generated)
- **NEVER** create documentation files unless explicitly requested
- **NEVER** create duplicate components
- **NEVER** bypass existing component patterns

### **Code Practices**

- **NEVER** use `const` for React component declarations
- **NEVER** skip file summary comments
- **NEVER** ignore TypeScript strict mode errors
- **NEVER** commit without running quality checks

### **Dependency Management**

- **NEVER** add dependencies without checking existing alternatives
- **NEVER** modify package.json without explicit user request
- **NEVER** use different versions of existing dependencies
